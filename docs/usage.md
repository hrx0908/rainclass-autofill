# 使用与故障排查

## 检查进度

“从头匹配”清除上次检查进度，重新从第 1 题读取。“继续匹配”保留已完成的结果，重试第一道未检查完成的题。例如第 20 题超时，前 19 题保留，继续时检查第 20 题。

进度在当前页面内存中，刷新页面后丢失；切换课程、章节、题库、作业，应用匹配设置或采用新的手工答案后需要从头检查。导出的 JSON 是结果报告，不能导入恢复进度。完整检查及试填前不能启动自动提交。

## 三类填充操作

- “填充本题”：匹配并填写当前题，不提交，可用于试填。
- “只填充已匹配题”：重新检查作业，填写匹配成功的可编辑题，再切题回读草稿；不点击提交。部分平台切题不能保留草稿，脚本遇到这种情况停止。
- “逐题填充并提交”：在完整检查、试填且允许使用的前提下，逐题填写、回读、提交并确认新反馈，默认跳过待核对题。

## 手工核对

图片选项、未匹配题或资料含文字差异时，在“预览本题”中选择或填写正确答案，点击“采用以上核对答案”，再从头检查。采用手工答案会清除旧检查计划。题干、图片或选项变更时，原手工结果失效。

普通文字题不按题号匹配。图片题的章节顺序模式仅在已确认页面与来源顺序一致时使用，参考答案必须能唯一定位选项或与空格数量对应。

## 常见停止原因

| 提示 | 处理方式 |
| --- | --- |
| 没找到答案控件、题型未适配 | 确认当前页面已加载；尝试导出诊断或手工处理 |
| 字体读取失败 | 检查静态资源请求及网络，恢复后重试；不要用乱码推测答案 |
| 切题超时 | 等页面加载完成，在相同页面点击“继续匹配” |
| 未提交草稿弹窗 | 用户核对并手动处理网页弹窗，脚本在检查时不代为提交 |
| 页面已有不同答案 | 默认保留，核对后再决定是否启用覆盖 |
| 提交失败或确认超时 | 查看真实页面结果并自行处理；脚本不会重复点击提交 |

提交反馈不等于成绩或答案已正确。所有真实操作均需符合学校、课程和平台规则。
